# Claudia Project Rules

## Conversation
- A bare "do" / "do it" / "yes" from the user means "continue", "keep going", "proceed". Resume the current task without asking for clarification.

## Codex — how to work (canonical docs)
Claudia uses the MindAttic **Codex** documentation standard. Treat these as the source of truth and keep a single home per fact (link by id; never restate):

- **`docs/BIBLE.md`** (L0) — what Claudia IS / is NOT, architecture, the Laws (`{#CLA-§N}`, `{#CLA-LAW-n}`), verified state, glossary. Inherits the org-wide [`MindAttic.HouseRules.md`](../MindAttic.HouseRules.md) — do not restate or modify house rules.
- **`docs/AMENDMENTS.md`** (L1) — append-only change log (`CLA-A<n>`); an amendment **wins** over the bible. Never rewrite one; supersede it.
- **`docs/USER_STORIES.md`** (L2) — stories (`CLA-US-<Epic><n>`); every `✅` cites its verifying check. Mark `✅` only when a check/build proves it ([HOUSE-LAW-8]).
- **`docs/rfc/`** — design notes; graduate into L0+L2 then mark superseded.
- **`docs/data/`** (L5) — `parts.index.json` mirrors the canonical catalog `config/parts.json` (the in-place store MindAttic.Deploy reads); `_schema/*.schema.json` validates it. Cite parts by id `part.<slug>`, never restate their fields.

**Before finishing any change**, run the doctor and refresh the digest (Windows PowerShell 5.1):

```
powershell -NoProfile -ExecutionPolicy Bypass -File tools/codex.ps1 digest
powershell -NoProfile -ExecutionPolicy Bypass -File tools/codex.ps1 doctor
```

`doctor` must exit 0. It checks front-matter, unique `{#...}` ids, resolving cross-refs, JSON + schema validity, catalog id uniqueness, that cited repo paths exist, and that `docs/BIBLE.digest.md` is not stale. The digest is regenerated by `tools/codex.ps1 digest` and injected at session start by `.claude/hooks/inject-digest.ps1` — never hand-edit `docs/BIBLE.digest.md`.
